## 강점 (유지)
1. **검증 규율 — 최상급.** OOF≈LB를 4회 독립 재확인(ADR #006). 모든 비교 동일 fold/seed(#002·#016) → OOF 신뢰로 제출 절약·반복속도 확보. Kaggle 핵심을 잠갔다.
2. **결정·실패 기록.** ADR 19개가 결정/근거/트레이드오프 + **기각의 메커니즘**(#009·#010·#012)까지. 통제실험으로 실패원인 확정(#012 R²=0.744). 재론 방지.
3. **멈출 줄 앎.** FE 공간 "소진"을 증거로 선언(#014/#015) 후 앙상블 전환.
4. **재현성·전이성.** seed/git hash 로깅, py3.11 pin(#008), fold 동결(#016), top 솔루션 리서치 기반 전략(#018).

## 비효율·리스크 (개선)
1. **자기 계획 위반(기록 안 함).** ADR #013(튜닝=앙상블 후)인데 M4 중 Optuna LGBM 선행. 유휴활용은 OK이나 **ADR 미개정 → 계획에서 벗어난 사실이 기록에 안 남음**. 결정로그가 강점이므로 어길 땐 한 줄 개정.
2. **RealMLP epoch/lr 토끼굴.** 블렌드 기여 +0.00007 보조모델에 128ep·lr0.07 등 다수 GPU런 투입 → "256ep/0.04 default가 최적"이란 결론만 얻고 성과 없이 종료. ROI 신호(단독 최약)는 일찍 나왔으나 중단 기준이 없었음.
3. **한계이득 제자리 추격.** M4가 +0.0001~0.0002 만 좇음(3-way Public +0.00019). 노력 대비 LB 이동 미미, 이득 점점 줄어듦. 정지조건 부재.
4. **인프라 투자 ≫ 성과.** 3일 Playground에 Kaggle runner + Lightning Jobs + 다단 리팩토링. 학습가치 있으나 본 목적과 무관한 곁가지 작업 혼입(예: 본 세션 Lightning 조사 = year-cat 측정에서 벗어난 우회).
5. **프로세스 격식 vs "바이브 코딩".** 커밋 ~40%가 `docs:`. 지식베이스론 훌륭하나 단기 컴피티션엔 문서 오버헤드.

## 사용자 응답 + 정정 (2026-06-04 대화)
리뷰 후 맥락 확인 → 비효율 지적 2건은 **의도된 투자**로 재해석(나는 의도를 모른 채 결과만 판단했음):
- **문서화 과투자 → 의도된 교정.** 과거 본인 약점이 "실험 과정 문서화 부족" → 이번에 의식적으로 강화. 옳은 방향. 남는 정제는 **타이밍**뿐: 결정·결론은 풍부히, *진행 중 탐색*의 실시간 문서화만 보류(막판에 폐기되면 부채 — 예: Lightning artifact 동작을 검증 전 단정→정정).
- **정식화/인프라 → 재활용성 메타목표.** "바이브 코딩을 ML에 처음 적용 → 재활용 스캐폴딩인가" 점검이 목적. 올바른 질문 = "과투자였나"가 아니라 **"무엇이 전이되나".**
- **토끼굴/과몰입 = 인정된 재발 약점**(과거 ML/DL 프로젝트서도 반복). → 의지 아닌 **구조적 가드** 필요.
